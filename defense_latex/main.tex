\chapter{Hybrid Split Parallelism}

\paraq{What has been established before this chapter, and what problem remains?}
In the preceding chapters we built \textbf{gsplit}, a partition-aware distributed
GNN training system, and showed that it trains correctly and outperforms the state of the art
across a range of settings. In gsplit, each GPU owns a METIS partition weighted by sampling
frequency, and sampling, feature loading, and the model forward/backward exchange only
boundary data across GPUs via NCCL. This chapter starts from a tension our ablation studies exposed:
\emph{the gain from gsplit is not uniform}---depending on the setting, gsplit can be faster or slower
than a data-parallel baseline.

\paraq{Which settings make gsplit's gain inconsistent, and why?}
Two model parameters change the cost of the cross-partition \textbf{shuffles}:
\textbf{depth} (every additional layer adds another all-to-all shuffle) and
\textbf{hidden size} (every shuffle moves a larger feature volume). Both also change the computation
and data-loading savings that splitting provides, so neither has a consistent effect: as models grow
deeper or wider, gsplit's training time relative to the baseline improves in some settings and
degrades in others, depending on the GNN model, the graph, and the interconnect. 

\paraq{What does this chapter do about it, and in what order?}
In this chapter, we (i)~\emph{quantify} how gsplit's gain over the DGL baseline varies
(Section~\ref{sec:limitations}); (ii)~propose \emph{two hybrid parallelism
schemes}---a data-parallel hybrid and a pipeline hybrid---that address the communication costs exposed by our system
(Section~\ref{sec:hybrids}); (iii)~introduce a \emph{floorline}, a lower bound on each strategy's
overhead whose ridge names the strategy to use, and condense it into rules of thumb for choosing a
strategy per layer (Section~\ref{sec:roofline}); and (iv)~check how often the floorline's pick
matches the measured winner across the full sweep (Section~\ref{sec:results}).

\paraq{On what hardware and workloads do we measure?}
\textbf{Experimental Setup.} All measurements run on a single node with $4{\times}$\textbf{A100-SXM4-80GB} GPUs
connected by NVLink. We emulate a PCIe-class interconnect on the same node by disabling NCCL
peer-to-peer transfers, which routes the same shuffles over the slower path without changing the
hardware.
% Detail: NVLink topology is NV12 (all pairs); the switch is NCCL_P2P_DISABLE=1.
DGL replicates the full graph on every GPU and gathers features over UVA from host-pinned memory.
% Detail (already stated above): gsplit runs at k=0; neither system uses a feature cache.
We train SAGE and GAT models with a neighbour fanout of \textbf{15} per layer and a
global batch size of \textbf{1024} (divided across the four GPUs). Each configuration runs for \textbf{3 epochs} with the feature cache disabled, and all
reported times are the mean \emph{per-epoch} time over these epochs. We evaluate
\textbf{products} and \textbf{papers100M}.
